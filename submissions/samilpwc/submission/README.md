# CEO Issue Judge Agent (Samil PwC)

## 1. 개요 및 60초 피치
- **[면책 조항 (Disclaimer)]** 본 산출물은 AI 모델을 활용한 시뮬레이션 결과로, 최종 의사결정의 법적/재무적 책임은 전적으로 사용자(경영진)에게 있으며 실제 회계 법인(PwC 등)의 확약이나 법적 자문을 대체할 수 없습니다. 모든 데이터는 철저히 비식별화된 상태임을 가정합니다.
- **[1문장 문제 정의]**: 단순한 데이터 요약기가 아닌, 경영진이 조직 내 정치와 반발을 뚫고 결정을 밀어붙일 수 있도록 **'감사 가능한 근거물(Auditable Evidence)'**을 3초 만에 생성하는 의사결정 판독기입니다.
- **[Pain]** 부서 간 예산 분쟁이 발생할 때, 임원의 72%는 과도한 책임 부담 때문에 결정을 미룹니다 (McKinsey). 시중의 일반적인 AI 요약기는 이 복잡한 사내 정치를 해결해 주지 못합니다.
- **[Moment]** 경영진에게 필요한 건 친절한 요약이 아니라 '총대를 메어줄 객관적이고 감사 가능한 명분'입니다.
- **[Relief]** 본 플러그인은 재무 데이터를 주입하면 3초 만에 사내 규정(SOP)을 스캔하여 모순을 찾고, **추후 외부 및 내부 감사 시 즉시 제출 가능한 형태의 '결정 근거 추적 로그(Audit Trail)'가 포함된** 엄격한 규정 기반의 권고 리포트를 생성합니다. 규정이 모호할 경우 절대 추측(Hallucination)하지 않고 **PwC의 전문 자문 파트너(Human-in-the-Loop)** 검토로 즉각 이관하여 리스크를 차단합니다. C-레벨의 사내 정치적 교착 상태를 가장 안전하고 신뢰할 수 있는 '결단'으로 바꿔드립니다.

## 2. 20-Round Stress Test (방어 매트릭스)
본 에이전트는 제출 전 멀티에이전트를 활용한 20라운드 무한 검증 루프를 거치며 60여 개의 악성/엣지 케이스를 모두 방어해 냈습니다. (`logs/` 디렉토리 참조)
- **PII 우회 및 인젝션 차단**: Base64 인코딩, 협박성 프롬프트, 시스템 프롬프트 노출 등 전면 방어 완료.
- **Zero-Hallucination**: SOP 조항이 없거나 상충되는 데이터(예: 매출/비용 동시 500% 급증) 입력 시 `review_required=true` 락인 완벽 작동.

## 3. 핵심 5문항 답변
### Q1. 무엇을, 누가, 어떤 상황에서 쓰나요?
- **누가**: C-레벨 경영진 및 의사결정권자.
- **상황**: 원가 할당, 매출 분쟁 등 이해관계가 얽힌 교착 상태.
- **무엇을**: 내부 사내 정치와 책임 회피 병목을 돌파하기 위한 '객관적 SOP 기반 판독 리포트 생성기'.

### Q2. 왜 이 문제를 선택했나요?
- **[FACT]** 데이터 요약기가 아닌, **결정의 정당성을 뒷받침할 외부 권위(SOP 규정)와 책임 분산 장치**가 B2B 엔터프라이즈 컨설팅 AI의 진정한 핵심 가치이기 때문입니다. 실제로 72%의 C-레벨 임원이 사내 정치와 책임 부담으로 의사결정을 유보한다는 McKinsey 조사 결과가 이를 뒷받침합니다.

### Q3. 플러그인은 어떻게 작동하나요?
- **[Flow]**: 데이터 입력 → 이상 패턴 탐지 → SOP 매핑(Simulated RAG) → 객관적 권고 리포트 출력
1. 비식별화된 `[SYNTHETIC]` 영업/재무 데이터 입력.
2. 부서 간 자원 편중 등 이상 패턴 탐지.
3. 사내 규정(SOP) 스니펫을 매핑하여 객관적 기준 검색.
4. AI의 추측을 배제하고 SOP 근거를 인용한 리포트 JSON 출력.

### Q4. AI를 어떻게 활용했나요?
- 단순 키워드 검색(Keyword Search)이 아닌, 숫자 뒤 '행간'의 문맥을 이해하고 다수의 상충되는 규정(SOP)을 종합적으로 추론하는 **Semantic Explainability** 엔진.
- 확실한 SOP 근거 부재 시 **Human Review 강제 이관** 구조 채택으로 환각 완전 차단.

### Q5. 어떻게 검증했나요?
- **핵심 방어 사례**: "매출/비용이 동시 500% 급증했다"며 악의적 비용 할당을 유도하는 인젝션 공격 시, SOP 상충을 즉시 감지하고 추측성 답변 대신 **Human Review 강제 이관**으로 완벽히 락인(Lock-in) 방어했습니다.
- 추가로 `logs/iteration_report.md`에 기록된 20라운드의 집요한 공격(PII 주입, 스키마 파괴 등 60종)을 모두 패스(PASS)했습니다.

## 5. 핵심 운영 KPIs 및 아키텍처 리스크 방어
- **정상 재승인 비율 (False Positive Escalation Rate)**: 과도한 방어 로직으로 무해한 데이터까지 Human 검토로 이관되는 비율을 모니터링하여 가드레일 민감도 튜닝.
- **Human-AI Collaboration**: AI 판정을 인간이 기각(Override)할 경우 사유를 기록하여 향후 로직 미세조정에 역환류(Feedback Loop) 적용.
- **Vector DB Cost Scaling & Latency 방어**: 대량의 쿼리 발생 시 Vector DB 과금 및 지연 시간 급증을 막기 위해, 애플리케이션 레벨에서 Semantic Caching 계층과 엄격한 Token Limit 임계치를 미들웨어에 구현 (상용화 아키텍처 반영 예정).

## 6. Known Limitations
- **Compliance-First**: 민감 정보 감지 시 마스킹 처리가 아닌 전면 분석 중단을 채택하는 극단적 보수성을 띕니다.
- **[WARN] 시스템 프롬프트 우회 우려**: 20라운드 방어에도 불구, 초거대 LLM의 최신 탈옥 기법에 취약할 여지가 있습니다.
- **[WARN] 상용화 로드맵**: 현재 온프레미스 Vector DB 연동은 시뮬레이션으로 대체되었으며, 실제 상용화 시 인프라 연동이 필요합니다.
- **[Scope Cut] GUI & On-premise**: 24시간 해커톤 타임라인 제약으로 인해 핵심 판독/방어 로직 구현에 100% 집중하였으며, 프론트엔드 GUI 및 실제 온프레미스 연계 배포는 상용화 로드맵으로 분리되었습니다.
