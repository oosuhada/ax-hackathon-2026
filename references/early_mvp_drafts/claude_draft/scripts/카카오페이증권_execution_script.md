# 실행 스크립트 — Claude Code / Codex CLI 에 순서대로 붙여넣기

⚠️ 이건 "미리 만든 대화 로그"가 아니라 "무엇을 시킬지"에 대한 지침입니다.
실제로 이걸 넣고 나온 결과를 보면서, 각 단계마다 대표님 판단으로 다음 프롬프트를
수정하거나 추가 질문을 하세요. 그 실제 과정이 logs/ 에 쌓여야 진짜 제출물이 됩니다.

---

## 준비
1. log-hooks.zip 설치 (아직 안 했으면)
2. 작업 폴더에서 Claude Code 실행: `claude` (또는 `codex`)
3. 아래 프롬프트를 순서대로, 한 번에 하나씩 넣기 — 결과 확인 후 다음으로 이동

---

## 프롬프트 1 — 프로젝트 초기화 확인
```
지금 mts-outage-companion이라는 Codex 플러그인을 만들고 있어.
src/.codex-plugin/plugin.json 이랑 src/skills/mts-outage-companion/SKILL.md 파일을
읽어보고, 지금 상태에서 뭘 더 채워야 하는지 요약해줘.
```

## 프롬프트 2 — 분류 로직 구현 요청
```
장애 설명 텍스트를 입력받아서 아래 4개 카테고리 중 하나 이상으로 분류하는
Python 스크립트를 만들어줘.

- ACCESS: 접속/로그인 지연·불가 (키워드: 접속, 로그인, 먹통, 튕김)
- ORDER: 주문 체결 오류 (키워드: 주문, 체결, 매수, 매도, 취소)
- QUOTE: 시세/차트 표시 오류 (키워드: 시세, 호가, 차트, 지연 표시)
- APP: 앱 크래시/기타 오류 (키워드: 앱, 오류, 강제종료)

키워드 매칭만으로는 부족할 수 있으니, 애매한 케이스를 어떻게 처리할지도
같이 제안해줘. 파일은 src/skills/mts-outage-companion/classify.py 로 만들어줘.
```

## 프롬프트 3 — 심각도 스코어링 추가
```
방금 만든 분류기에 심각도 스코어링 기능을 추가해줘.
심각도 = 영향받은 기능 수 × 장애 지속시간 가중치 × 반복여부 가중치 로 계산하고,
입력에 지속시간이나 반복여부 정보가 없으면 사용자에게 물어보거나 기본값을
쓰도록 설계해줘. 어떤 방식이 나을지 너 생각도 알려줘.
```

## 프롬프트 4 — 고객 공지 템플릿 생성기
```
분류 결과와 심각도 점수를 입력받아서, 아래 구조의 한국어 고객 공지 초안을
자동 생성하는 함수를 추가해줘.

1. 제목: [서비스명] 서비스 일시 장애 안내
2. 무엇이 발생했나 (사실 기반)
3. 언제부터 언제까지
4. 어떤 조치를 취했나
5. 보상/조치 여부
6. 재발방지 약속

과장되거나 법적 리스크가 될 만한 표현(예: 100% 보상 약속 같은 확정적 문구)은
피하고, 대신 "검토 중"처럼 안전한 톤으로 써줘.
```

## 프롬프트 5 — 테스트
```
아래 3개 케이스로 지금까지 만든 걸 테스트해줘.

케이스1: "오전 9시 15분부터 20분간 매수 주문이 체결되지 않았습니다"
케이스2: "앱 접속이 아예 안 되고 로그인 화면에서 멈춰있습니다. 30분째입니다"
케이스3: "차트 시세가 실시간이 아니라 5분 전 데이터로 보입니다"

각각 어떤 분류/점수/공지초안이 나오는지 보여주고, 이상한 부분 있으면
너가 먼저 지적해줘.
```

## 프롬프트 6 — README/질문 5문항 업데이트 요청
```
지금까지 만든 내용을 바탕으로 README.md의 질문 5문항(무엇을·누가·어떤상황,
왜 이 문제를 선택했나, 어떻게 작동하나, AI를 어떻게 활용했나, 어떻게 검증했나)
답변을 다시 써줘. 특히 "AI를 어떻게 활용했나"는 지금까지 우리가 주고받은
과정(분류 로직 설계 → 스코어링 추가 → 템플릿 생성 → 테스트) 을 실제로
반영해서 써줘.
```

```
넣으세요. 이 부분부터는 미리 써드릴 수 없어요 — 실제로 나온 결과를 보고
판단하셔야 하는 지점이에요.]
```
