# 00. 로그 정책 및 주의사항

해커톤 안내문은 다음을 요구합니다.

- 플러그인을 만들면서 AI와 주고받은 대화 로그를 `logs` 폴더에 함께 제출
- 편집·발췌 없이 전체를 그대로 제출
- 제출 가능한 형식: `md`, `txt`, `json`, `jsonl`
- 로그·플러그인·질문지 사이의 정합성 평가
- 사후 가공, 편집, 발췌, 삭제 시 실격 가능
- AI 채팅에 API 키, 비밀번호, 토큰 등 비밀정보 입력 금지

## 안전한 작업 방식

1. 기업별로 새 채팅 세션을 시작한다.
2. 이 팩의 프롬프트를 순서대로 붙여넣는다.
3. AI 답변을 바탕으로 실제 파일을 만든다.
4. 대화가 끝난 뒤 전체 대화를 그대로 복사해 `logs/<company>_raw_log.md`로 저장한다.
5. 로그에서 내용을 삭제하거나 수정하지 않는다.
6. 민감정보가 들어간 경우, 그 로그를 편집하지 말고 작업 세션을 폐기한 뒤 민감정보 없이 새로 시작한다.

## 하면 안 되는 것

- 이 팩의 `SIMULATED_LOG_EXAMPLE.md`를 실제 작업 로그처럼 제출
- AI가 실제로 말하지 않은 내용을 로그에 추가
- 불리한 시행착오를 삭제
- 출처 없는 숫자나 기업 내부정보를 근거처럼 작성
- 공개 자료로 확인되지 않는 주장을 문제정의에 넣기

## 제출용 로그에 들어가면 좋은 실제 흐름

- 문제정의 후보 논의
- 공개 근거 수집 계획
- 플러그인 구조 설계
- `plugin.json` 작성
- `SKILL.md` 작성
- 샘플 입력/출력 설계
- 검증 기준 설계
- README 5문항 답변 작성
- 최종 정합성 검사
