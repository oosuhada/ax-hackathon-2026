# AX 해커톤 예선 로그 생성용 프롬프트 런북

> 목적: 이 문서는 **가짜 제출 로그**가 아니라, 실제 AI 도구와 주고받을 대화를 만들기 위한 **복붙용 프롬프트 시나리오**입니다.  
> 해커톤 안내상 `logs/`에는 AI와 주고받은 원본 대화 전체를 편집·발췌 없이 제출해야 하므로, 이 파일 자체를 `raw log`로 제출하지 말고, 아래 프롬프트를 실제 ChatGPT/Codex/Claude Code/Cursor 세션에 순서대로 입력한 뒤 그 세션의 전체 대화를 저장하세요.

## 핵심 원칙

1. **기업별로 별도 세션**을 여는 것이 가장 안전합니다.  
   - `kakaopaysec_raw_log.md`
   - `musinsa_raw_log.md`
   - `samilpwc_raw_log.md`

2. 각 세션 첫 메시지에 아래를 명시하세요.
   - 이 작업은 AX 해커톤 예선 제출물 제작 과정이다.
   - 로그는 원본 그대로 제출되어야 하므로 응답에서 비밀정보 입력을 요구하지 말 것.
   - 공개자료 기반 문제정의, 플러그인 설계, 파일 수정, 검증까지 순차적으로 진행할 것.

3. **민감정보 금지**
   - API Key, 비밀번호, 개인 토큰, 실제 고객 데이터, 기업 내부자료를 절대 붙여넣지 마세요.

4. **사후 조작 금지**
   - 실제 로그에는 프롬프트와 AI 응답을 편집하지 마세요.
   - 실수한 내용도 그대로 두는 게 원칙입니다.
   - 단, 제출 전 개인정보/비밀정보가 들어갔다면 실격 리스크가 생기므로 애초에 넣지 않는 게 중요합니다.

5. **로그와 제출물의 정합성**
   - README에 “AI로 했다”고 쓴 작업은 실제 로그에 있어야 합니다.
   - 로그에 없는 출처·검증·기능을 README에 쓰면 불리합니다.

## 권장 세션 구조

각 기업별로 아래 8단계 프롬프트를 진행합니다.

1. 문제 후보 탐색 및 공개자료 근거 수집
2. 최종 문제정의 확정
3. 플러그인 사용자/상황/입출력 정의
4. Codex Plugin 구조 설계
5. SKILL.md 작성/개선
6. README 5문항 초안 작성
7. 테스트 데이터와 검증 시나리오 생성
8. 최종 제출 전 정합성 검토

## 실제 로그 파일 작성 방식

ChatGPT 웹을 쓴다면 세션 전체를 복사해서 다음 형식으로 저장하세요.

```md
# Raw AI Conversation Log — <기업명>

- Tool: ChatGPT Web / Codex CLI / Claude Code / Cursor 등
- Date: 2026-07-XX
- Purpose: AX Hackathon preliminary submission development

---

<여기부터 실제 대화 전체를 편집 없이 붙여넣기>
```

Codex CLI나 Claude Code에서 log-hooks를 쓴다면 자동 생성된 로그를 그대로 제출하세요.
